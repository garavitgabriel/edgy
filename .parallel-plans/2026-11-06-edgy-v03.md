## What we're building

v0.2 shipped 28 actions and a settings layer, verified on both Macs. Hardware testing and user research left this list:

1. **Native overlay.** Our volume/brightness HUD is the legacy overlay; the keyboard keys show the current system animation (and the right one for AirPods etc.). Fix: slides drive the volume/brightness the way the keys do, so macOS draws its own current HUD.
2. **Every Mac.** On a Mac mini there is no built-in display; brightness does nothing and nothing says why. Edgy must know what each action can do on this machine (`ActionPerforming.availability(of:)`), control external monitors where possible (DDC/CI, Apple displays), and choose first-run defaults that work on this machine.
3. **New actions:** slide-to-switch-apps (bottom edge), hold-a-key (push-to-talk for dictation apps), macOS Dictation, keyboard backlight (MacBook), and window snap that exits full screen first.
4. **Fewer misfires.** The misfire defense is built but untuned; harden it against adversarial scenarios and real traces.

## New contracts already on `main` (chief)

- `ActionDescriptor.Shape.hold` — driven only by `.longPress`. `ActionInput.press(down:)` — `down: true` when the hold is recognized, `down: false` at lift/cancel, always paired.
- `GestureEvent` long-press phases: `.began` when recognized, `.ended` at lift, `.cancelled` if taken away. (Today the pipeline emits a single `.ended` at recognition; batch 9 changes that.)
- `ActionAvailability` (`available` / `limited(reason:)` / `unavailable(reason:)`) and `ActionPerforming.availability(of:)` (defaults to `.available`).
- New module **`Displays`** (`Sources/Displays/Displays.swift`): `DisplayInfo`, `DisplayBrightnessControlling`, `DisplayBrightnessError`, frozen factory `makeLiveDisplayBrightness()` (placeholder returns no displays). `Actions` depends on it.

Need anything else in `EdgyCore`, `Package.swift`, or the Displays contract types? Write a blocker; don't edit them.

## Hard rules across all worktrees

1. **Take the time you need.** Correctness > speed.
2. **Verification triple green before DONE**, run in your transcript, plus the denylist.
3. **Stay in your glob.** Need something outside it? Write `blockers-batch-N.md` and STOP.
4. **Never touch the real system from tests** (CLAUDE.md rule 1): no key or media events, no brightness/volume/backlight changes, no DDC writes, no display probing, no app launches. Live paths sit behind protocols with mocks; manual `scripts/smoke-*.sh` scripts are for Gabriel.
5. **Frozen signatures** (`makeLive…` factories, `makeGestureRecognizer`, the Displays contract types) stay exactly as on `main`.
6. **Private frameworks** load at runtime by name (CFBundle / dlsym), never linked; every lookup failure degrades with one logged reason (CLAUDE.md rule 6).
7. **Commit small and often**, your branch only. Never `--amend`, never rewrite history, never commit past a failing step.
8. **No third-party product names** anywhere — code, comments, docs, commits (this includes names of other apps that users mention, e.g. dictation apps: say "a dictation app's push-to-talk key").
9. **Own work only.** Outside code is reference for learning, never copied.
10. **Human-only steps** (feeling, seeing a HUD, plugging a monitor, recording traces) are never part of your proof. List them under "Needs Gabriel" and finish.
11. **Close with `/builder-close`.** It must commit ONLY your own return file in the vault (`git add <that one path>`), never `git add -A` — other sessions have uncommitted work there. Never reset, revert or rewrite the vault's history.
