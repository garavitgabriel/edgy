## What we're building

v0.1 works on hardware: edges and corners drive volume, brightness, mute, mic mute, media keys and Shortcuts, with haptics and per-app profiles, configured by hand-editing JSON. A separate design session is producing the settings window and onboarding. v0.2 builds everything that window will need **without building the window**:

- **Batch 5 (EDGY-ACTIONS-2)** grows the action catalog from 8 to ~25: keyboard shortcuts, slide-to-repeat keys, open app/URL/file, Mission Control family, Spaces, window snapping, lock/sleep display. Every action describes its parameters so the UI can build controls from data.
- **Batch 6 (EDGY-SETTINGS)** builds the settings layer the window will bind to: a `SettingsEditor` (edit, validate, undo/redo, save, apply live), permission state, and an engine status snapshot. The menu bar's existing items go through it.

## New contracts already on `main` (chief, commit before this brief)

- `ActionDescriptor` gained `category: ActionCategory` and `parameters: [ActionParameter]` (both defaulted). `ActionParameter` has `key`, `kind` (`text`, `keyCombo`, `appBundleID`, `url`, `filePath`, `number(range)`, `choice([String])`), `required`, `defaultValue`, `displayName`.
- `KeyCombo` (`Sources/EdgyCore/KeyCombo.swift`): the string format for shortcuts in `Binding.parameters`, e.g. `"cmd+shift+4"`. `KeyCombo.keyNames` is the full key vocabulary.
- `Zone.supports(_ gesture:)`: corners → tap/double-tap/long-press only; edges → slide, tap, double-tap, long-press, and swipes along their own axis.
- Live haptics: a click (`strongTick`) is now a double pulse so it feels different from a slide tick.

Need anything else in `EdgyCore`? Write a blocker; do not edit it.

## Hard rules across both worktrees

1. **Take the time you need.** Correctness > speed.
2. **Verification triple green before DONE**, run in your transcript, plus the denylist check.
3. **Stay in your glob.** Need something outside it? Write `blockers-batch-N.md` and STOP.
4. **Never touch the real system from tests** (CLAUDE.md rule 1): no key events, app launches, window moves, URL opens, `pmset`, permission prompts. Every live output sits behind a protocol with a mock.
5. **Frozen factory signatures** (`makeLiveActionRegistry(settings:)` etc.) stay exactly as on `main`; replace bodies only.
6. **Commit frequently**, small commits, your branch only. Never `--amend`, never rewrite history, never commit if lint fails (no `;`-chained commits that skip a failing step).
7. **No third-party product names** anywhere — code, comments, docs, commits.
8. **Own work only.** Outside code is reference for learning, never copied.
9. **Human-only steps** (feeling haptics, granting permissions, pressing real gestures) are never part of your proof — list them under "Needs Gabriel" and finish.
10. **Close with `/builder-close`**, never `/end-of-session`.
