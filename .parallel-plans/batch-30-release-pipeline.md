## Build
1. **One version source.** The version comes from the git tag (`vX.Y.Z` → `CFBundleShortVersionString`), the build number from the commit count (monotonic); `bundle.sh` and `release.sh` stamp the copied `Info.plist`, never the checked-in one. A dev build off a tag reads `X.Y.Z-dev+<short sha>`. Print `version (build) commit` at the end of every bundle.
2. **`scripts/release.sh`**: release build → bundle into `build/release/Edgy.app` → sign with a **Developer ID Application** identity found in the keychain, hardened runtime (`--options runtime`, `--timestamp`), verify (`codesign --verify --strict --deep`, `spctl --assess`) → `make-dmg.sh` → sign the DMG → `notarytool submit --wait` with a keychain profile named by `EDGY_NOTARY_PROFILE` → `stapler staple` app and DMG → print SHA-256. Each stage is a function with a clear failure message. Flags: `--dry-run` (print every command, run none that sign or upload) and `--skip-notarize`. With no Developer ID identity it stops with one line saying what's missing; it never falls back to ad-hoc or the development identity.
3. **`scripts/make-dmg.sh`**: a drag-to-Applications disk image built with `hdiutil` only (no outside tools): the app, an Applications alias, volume name "Edgy", volume icon from `Resources/AppIcon.icns`. A background image is optional; if you add one, build it from `docs/design/assets/` (read-only) and never redraw the mark.
4. **Hardened runtime, proven not assumed.** Edgy loads private frameworks by name at runtime and installs event taps. `scripts/smoke-hardened.sh` (a human runs it; it explains each step): builds `build/release/Edgy.app` signed with the local development identity plus `--options runtime`, tells the human to quit Edgy and launch it, then lists what to check (touch input on the mirror, a gesture fires, volume + brightness + native indicator, Hold Keys, Switch Apps, key recorder, displays) and which log line proves each (`/usr/bin/log show … subsystem == "com.garavit.edgy"`). Add an entitlement only if a check fails without it; write each one, and the failure it fixes, in `docs/RELEASING.md`.
5. **`Makefile`**: `make app` (the free path: release build, local signing with the development identity if present, else ad-hoc with a printed note that Accessibility must be re-granted after each rebuild; output `build/release/Edgy.app`; never installs or launches), `make dmg`, `make release`, `make clean`.
6. **`docs/RELEASING.md`**: one page: prerequisites (Developer ID certificate, the notary keychain profile and the exact `notarytool store-credentials` command with placeholders), the release steps, how to verify a download on a clean Mac (`spctl`, `stapler validate`), rollback, and "what is not automated yet" (the auto-update feed).
