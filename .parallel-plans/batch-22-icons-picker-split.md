## Two phases (the polish batch 21 owns Picker/ and Inspector/ until it merges)

**Phase A — now:** you own `Sources/EdgyUI/Icons/**` (new folder), `Tests/EdgyUITests/Icons/**`, `docs/design/build-shots/batch-22/**`.
1. **The action icon family — transcribed, not drawn.** The design session exports every action icon and the split diagrams as SVGs to `docs/design/assets/icons/` (16×16 viewBox, 1.5 stroke, `currentColor`, file names = catalog ids, plus a README mapping file → id). Transcribe each into code under `Icons/` (SwiftUI `Path`s generated faithfully from the SVG paths, or bundled template PDFs — pick one, justify it, and never redraw by eye). Never SF Symbols or stock glyphs for actions. Public API: `ActionIcon(id: ActionID, size: CGFloat = 16)` (colour from the environment/`Tokens`) and `ActionIcons.has(_:)`. A test proves every id in the real catalog (`makeLiveActionRegistry(settings: .defaults).available`) has an icon, and a test compares each transcribed icon's bounds to its SVG viewBox. If the folder isn't there yet when you start, write a blocker and wait — don't invent icons.
2. A **split-control drawing** (from the exported split diagrams where provided): `EdgySplitGlyph(edge:parts:selected:)` — this edge in its orientation (40×12 top/bottom, 12×40 left/right), divided into 1–4 parts, selected one filled `ink`, no numbers.
3. Snapshots: an icon sheet (all actions, light/dark, 16 pt and 2×) and the split glyphs (both orientations, every count, selected/unselected).
