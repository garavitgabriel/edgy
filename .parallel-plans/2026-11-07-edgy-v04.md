## What we're building

v0.3 shipped and Gabriel tested it on the Mac mini with no issues. The settings window is being designed in a separate session; its **bones are fixed** even though its look isn't: a live mini trackpad mirror with touches, a Test Mode that shows each touch as recognized or rejected, conflict notes on the zone editor ("each double-tap fires tap first"), a category-grouped action picker with dimmed unavailable items, per-app profile chips, Enabled + Test Mode in the menu dropdown.

v0.4 builds everything under those bones, so the window is mostly layout when the design lands:

1. **Per-app profiles that override, not replace.** Gabriel hit this on hardware: a Ghostty profile copied the defaults, so changing one gesture meant owning all of them. Now an app profile can inherit the default and override single gestures, or turn one off for that app.
2. **Every gesture is honest.** A physical click-and-drag along an edge is never a gesture. A tap in a zone that also has a double-tap waits for the double-tap window instead of firing first.
3. **Push-to-talk on any key, including `fn` alone** (dictation apps default to it), with a stuck-key watchdog.
4. **UI-facing model:** live touch/decision feed, Test Mode, profile overrides, conflict notes, pickers (installed apps, Shortcuts, key recorder), and a written, tested settings reference that proves every setting is reachable.

**Not in v0.4:** any SwiftUI/AppKit view, window, layout, copy for zone labels. Import/export (defer).

## New contracts already on `main` (chief, commit after `cea0be9`)

- `KeyCombo.key` is now `String?`; modifier-only combos parse (`"fn"`, `"ctrl+opt"`), `init?(modifiers:)`, `isModifierOnly`. Actions call sites were patched minimally to compile (a modifier-only combo can be held but `post` throws).
- `TouchFrame.buttonDown: Bool` (decodes as `false` when absent) and `RejectionReason.physicalClick`.
- `GestureContext.doubleTapZones: Set<Zone>?` (same pattern as `slideZones` / `longPressZones`).
- `Profile.inheritsDefault: Bool` (decodes `false` when absent = old full-replace behaviour) and `ActionID.doNothing` (`"edgy.none"`). `EdgyConfig.profile(for:)` now **resolves**: merges an inheriting app profile over the default (same zone + gesture → app wins) and drops `doNothing` bindings. Tested in `Tests/EdgyCoreTests/ContractsTests.swift`.
- `GestureSettings.defaults.cornerSizeMM` stays 12 for now; batch 10 makes the gesture tests independent of the default, then the chief flips it to 10 after merge.

Need anything else in `EdgyCore`, `Package.swift`, or the Displays contract? Write a blocker; don't edit them.

## Hard rules across all worktrees

1. **Take the time you need.** Correctness > speed.
2. **Verification triple green before DONE**, run in your transcript, plus the denylist.
3. **Stay in your glob.** Need something outside it? Write `blockers-batch-N.md` and STOP on that item; continue the rest.
4. **Never touch the real system from tests** (CLAUDE.md rule 1): no key or mouse events, no event taps, no app launches, no `shortcuts` process, no filesystem scans outside temp dirs. Live paths sit behind protocols with fakes; manual smoke scripts are for Gabriel.
5. **Frozen signatures** (`makeLive…` factories, `makeGestureRecognizer`, EdgyCore contracts) stay exactly as on `main`. Additive public API in your own module is fine; document it.
6. **Private frameworks** load at runtime by name, never linked; every lookup failure degrades with one logged reason.
7. **Commit small and often**, your branch only. Never `--amend`, never rewrite history, never commit past a failing step.
8. **No third-party product names** anywhere — code, comments, docs, commits (say "a dictation app's push-to-talk key", "a terminal app").
9. **Own work only.** Outside code is reference for learning, never copied.
10. **Human-only steps** (feeling, seeing, clicking on hardware) are never part of your proof. List them under "Needs Gabriel" and finish.
11. **Close with `/builder-close`.** It must commit ONLY your own return file in the vault (`git add <that one path>`), never `git add -A` — other sessions have uncommitted work there. Never reset, revert or rewrite the vault's history.
